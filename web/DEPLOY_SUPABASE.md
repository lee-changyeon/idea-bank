# 사용자 웹(web/) 온라인 배포 — Vercel + Supabase 설계 메모

> 목표: `web/` 사용자 앱을 Vercel(파이썬 서버리스 함수) + Supabase(Postgres + Storage)에서 돌린다.
> 관리자 사이트(`admin/`)는 지금처럼 로컬에서만 쓴다. 로컬 SQLite 모드는 그대로 둔다.

## 1. 한눈에 보기

| 지금 (로컬) | 온라인 (Vercel + Supabase) | 바꾸는 곳 |
|---|---|---|
| SQLite `web/data/ideabank_web.db` | Supabase Postgres (`DATABASE_URL`) | `ibweb/db.py` → `open_db()` 가 둘 중 하나를 고름 |
| `BEGIN IMMEDIATE` 로 쓰기 직렬화 | 트랜잭션 + `pg_advisory_xact_lock(상수)` | `PgDB.tx()` |
| 첨부·계약서 파일 `web/data/files/<sha256>` | Supabase Storage 비공개 버킷 `ideabank-files/<sha256>` | 새 `ibweb/files.py` |
| `http.server` 로 상시 실행 | Vercel 함수 `api/index.py` 가 같은 `Handler` 클래스를 씀 | `httpkit.py` 는 거의 그대로 |
| 공인 시각 백그라운드 스레드 | ① 요청 안에서 바로 시도(짧은 시간 제한) ② Vercel Cron `GET /api/cron/tsa` | `ledger.Stamper` |
| 로그인 실패 제한: 프로세스 메모리 | DB 표 `login_fails` (함수 인스턴스가 여러 개라서) | `security.Throttle` |
| 쿠키 `HttpOnly; SameSite=Strict` | + `Secure` (`VERCEL` 또는 `IB_SECURE_COOKIES=1` 일 때) | `httpkit.App.set_cookie` |

`DATABASE_URL` 이 없으면 모든 것이 지금과 똑같이 SQLite + 로컬 파일로 돈다. `python web/server.py`, `run_web.bat`, `admin/server.py`, `tests/` 는 바뀌지 않는다.

## 2. 바꾸지 않는 것 (증명 호환성)

- 정규화 JSON(`ideabank/1`), `content_hash = sha256(payload)`, `entry_hash = sha256(prev:seq:content_hash)` 규칙은 `ideabank.canonical` 을 그대로 쓴다.
- 원장 payload 는 `BYTEA` 로 바이트 그대로 저장한다. 문자열로 바꾸지 않는다 → 해시가 같다.
- 증명 파일(zip) 구조와 VERIFY.txt 는 `proof.make` 그대로. 그래서 온라인에서 받은 증명 파일도 v1 검증기로 통과한다.
- 감사 로그(audit) 해시 체인 규칙도 그대로.

## 3. DB (`ibweb/db.py`)

- `open_db()` — `DATABASE_URL` 이 `postgres://` 또는 `postgresql://` 로 시작하면 `PgDB`, 아니면 기존 `DB`(SQLite).
- `PgDB` 는 `DB` 와 같은 메서드(`q`, `one`, `val`, `exec`, `tx`, `lock`)를 가진다. 서비스 코드는 SQL 을 거의 고치지 않는다.
  - `?` 자리표시자는 `%s` 로 바꾼다. `LIKE` 는 SQLite 처럼 대소문자를 가리지 않도록 `ILIKE` 로 바꾼다.
  - 행 객체는 `r["열"]` 과 `r[0]` 둘 다 되게 한다 (sqlite3.Row 와 같게).
  - `cur.lastrowid` 가 필요한 INSERT(`users`, `loans`, `contracts` 등 `id` 자동 번호 표)는 `RETURNING id` 를 붙여 같은 값을 준다.
- 스키마 차이: `BLOB`→`BYTEA`, `REAL`→`DOUBLE PRECISION`, 자동 번호 `id`→`BIGINT GENERATED BY DEFAULT AS IDENTITY`. `events.seq`·`ideas.seq`·`audit.id` 는 앱이 번호를 정하므로 그냥 `BIGINT PRIMARY KEY`.
- 스키마는 첫 연결 때 `events` 표가 없으면 만든다(`web/ibweb/schema_pg.sql`). 사용자가 SQL 을 따로 붙여 넣을 필요가 없다.
- **원장 직렬화**: `tx()` 는 `BEGIN` 직후 `SELECT pg_advisory_xact_lock(7243100)` 을 잡는다.
  - SQLite 의 `BEGIN IMMEDIATE` 와 같은 뜻(쓰기는 한 번에 하나)이다. 그래서 `MAX(seq)+1`, 대출·계약 번호, 감사 로그 번호를 계산하는 기존 코드가 그대로 안전하다.
  - 잠금은 트랜잭션이 끝나면 풀리므로 Supabase 트랜잭션 풀러(6543)에서도 쓸 수 있다.
- 추가 보호(Postgres 만):
  - `events` 표는 트리거로 `DELETE` 와 `seq`·`payload`·해시 열의 `UPDATE` 를 막는다. 공인 시각 열(`tsa_*`)만 바꿀 수 있다.
  - Supabase 는 `public` 스키마를 REST API(anon 키)로 열어 두므로, 모든 표에 RLS 를 켜고 정책을 두지 않으며 `anon`, `authenticated` 권한을 거둔다. 서버는 `postgres` 역할로 접속하므로 영향이 없다.
- 연결: Supabase **트랜잭션 풀러** 주소(포트 6543)를 쓴다. psycopg 3 에서 `prepare_threshold=None` 으로 준비된 문장을 끈다(풀러 요구 사항). 함수 인스턴스마다 연결 1개를 재사용하고, 끊기면 다시 연결한다.
- 드라이버: `psycopg[binary]` 하나만 추가한다(`requirements.txt`). 표준 라이브러리만 쓰는 원칙의 유일한 예외이며 Postgres 모드에서만 import 한다.

## 4. 파일 (`ibweb/files.py`)

- `put(sha, data)`, `get(sha)`, `exists(sha)` 세 함수만 둔다.
  - 로컬: `web/data/files/<sha256>` (지금과 같음).
  - 온라인: Supabase Storage REST API(`/storage/v1/object/<버킷>/<sha256>`)를 `urllib` 로 부른다. 키는 서비스 역할 키(`SUPABASE_SERVICE_ROLE_KEY`), 버킷은 비공개(`ideabank-files`). 버킷이 없으면 처음 쓸 때 만든다.
- 파일 이름은 내용의 sha256 이라 같은 파일은 한 번만 저장되고, 저장 뒤에는 바뀌지 않는다(`x-upsert: false`).
- 쓰는 곳: 아이디어 첨부(등록), 계약서 파일(관리자), 증명 파일 만들기, 원장 무결성 검사(첨부 해시 재계산), 첨부 내려받기.
- NDA 서명 문서는 원장 이벤트 payload 그 자체(`events.payload`, `ndas.doc`)라 DB 에 남긴다. 체인 검증에 바이트 원본이 필요하기 때문이다.
- 제약: Vercel 함수 요청 본문은 4.5MB 까지다. 첨부는 base64 JSON 으로 오므로 온라인에서는 **한 번 등록에 첨부 합계 약 3MB** 로 제한하고 화면에도 그 한도를 보여 준다(`/api/me` 의 `limits.max_upload`). 20MB 첨부는 후속 작업(Storage 서명 업로드 URL 로 브라우저가 직접 올리고 서버가 해시 확인).

## 5. 공인 시각 (RFC 3161)

- 등록·NDA 서명: 지금처럼 요청 안에서 바로 받는다.
- 나머지 이벤트(열람, 공개 단계 변경 등): 로컬은 백그라운드 스레드. 온라인은 스레드가 요청 뒤에 살아 있지 않으므로
  - 같은 요청 끝에서 대기 이벤트를 최대 몇 건, 약 4초 안에서 바로 처리한다(`InlineWake`).
  - 놓친 것은 Vercel Cron 이 `GET /api/cron/tsa` 를 불러 다시 시도한다. `Authorization: Bearer <CRON_SECRET>` 가 맞을 때만 동작한다. Hobby 요금제는 하루 1번이 한도라 매일 1번으로 둔다.
- TSA 로는 지금처럼 해시 32바이트만 나간다.

## 6. HTTP (`httpkit.py`, `api/index.py`)

- Vercel 파이썬 런타임은 `api/*.py` 의 `handler`(`BaseHTTPRequestHandler` 하위 클래스)를 부른다. 기존 `Handler` 를 그대로 쓴다.
- `vercel.json` 은 `builds`(`@vercel/python`, `api/index.py`) + `routes` 로 모든 경로를 이 함수로 넘긴다. 함수가 정적 파일(`web/static`)도 직접 준다. 보안 헤더·CSP 가 정적 파일에도 똑같이 붙는다.
  - `functions` 설정만 쓰면 Vercel 이 `api/index.py` 를 함수로 인식하지 못해 빌드가 실패했다(`unused_function`). 그래서 `builds` 로 명시한다.
- 접속 IP 는 `X-Forwarded-For` 의 첫 값을 쓴다(Vercel 일 때만 믿는다).
- 쓰기 요청의 `Origin` 검사, CSRF, `Content-Type` 검사는 그대로.
- 사용자 웹에 공개 `GET /api/ledger/verify`(원장 무결성 검사: 해시·순번·공인 시각·첨부 해시, 내용은 돌려주지 않음)를 더한다. 검증 화면에 [원장 무결성 검사] 버튼을 둔다.

## 7. 환경 변수 (Vercel 에만 넣는다 — 저장소에는 절대 넣지 않는다)

| 이름 | 값 |
|---|---|
| `DATABASE_URL` | Supabase → Connect → Transaction pooler 주소 (포트 6543, 비밀번호 포함) |
| `SUPABASE_URL` | `https://<프로젝트>.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API Keys → service_role(secret) 키 |
| `CRON_SECRET` | 아무 긴 무작위 문자열 (Vercel Cron 이 자동으로 Bearer 로 보냄) |
| `IB_STORAGE_BUCKET` | (선택) 기본 `ideabank-files` |

## 8. 배포 방식

- 새 Vercel 프로젝트(예: `idea-bank-web`)를 GitHub `lee-changyeon/idea-bank` 에 연결하고 **Root Directory 는 저장소 루트**로 둔다(`ideabank/` 코어 패키지를 import 해야 하므로).
- 기존 `idea-bank-meeting` 프로젝트(Root Directory `meeting/`)는 건드리지 않는다. 루트의 `vercel.json` 은 그 프로젝트에 영향을 주지 않는다.
- `.vercelignore` 로 함수 묶음에서 문서·회의실·v1 정적 파일 등을 뺀다.
- 온라인 DB 는 빈 상태로 시작한다(데모 데이터 없음).

- 주소: https://idea-bank-web-omega.vercel.app (Vercel 프로젝트 `idea-bank-web`)

- 확인한 보안: anon 키로 REST API 를 불러도 `users`·`events` 를 읽을 수 없다(permission denied). `/api/cron/tsa` 는 비밀 값 없이 부르면 403 을 준다.

## 10. DB 비밀번호 바꾸기

1. Supabase → Database → Settings → **Reset password**. 영문과 숫자로만 정하세요. 특수문자는 주소에서 깨집니다.
2. Vercel → Environment Variables → `DATABASE_URL` → Edit 에서 비밀번호 부분을 바꾸고 Save 합니다.
   - 본인 확인 코드까지 입력해야 저장됩니다. 목록에 "Updated just now" 가 보이는지 확인하세요.
3. **다시 배포**해야 적용됩니다. Deployments → ⋯ → Redeploy, 또는 `main` 에 푸시하면 됩니다.
4. 연결에 실패하면 Vercel Runtime Logs 에서 `[DB] 연결 실패` 줄을 찾습니다.
   - 사용자 이름·호스트·포트·비밀번호 길이가 나옵니다. 비밀번호 자체는 남기지 않습니다.
