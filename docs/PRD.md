# 아이디어뱅크 (Idea Bank) — PRD

> 제품 요구사항 정의서 · v0.2 · 2026-11-18 (v0.2: 1호 아이디어 "아이디어 대출" 모델을 사업 비전·로드맵에 반영)

## 1. 배경과 문제

- 많은 아이디어는 **특허로 보호하기 어렵거나**(추상적 개념, 비즈니스 모델, 기획안, 디자인 콘셉트, 노하우), **특허 비용·기간 대비 실익이 없어** 출원되지 않는다.
- 이런 아이디어는 나중에 분쟁(아이디어 탈취, 공동 창작 기여도, 선사용 주장)이 생겼을 때 **"내가 언제 이 아이디어를 가지고 있었는가"를 입증할 수단이 없다.**
- 메모 앱·이메일·문서 파일의 날짜는 쉽게 조작할 수 있어 증거력이 약하다.
- 좋은 아이디어가 있어도 **사업화할 자원이 없어 묻히고**, 반대로 새 사업 아이템이 필요한 기업은 **아이디어를 안전하게 얻을 통로가 없다.** 아이디어를 건넸다가 탈취당하는 일이 두려워 거래 자체가 일어나지 않는다.

## 2. 제품 목표

| # | 목표 | 성공 기준 |
|---|------|-----------|
| G1 | 형식 제약 없이 아이디어를 자유롭게 기술·보관 | 텍스트 + 첨부파일로 1분 안에 등록 |
| G2 | 아이디어의 **창안 시점을 제3자가 검증 가능**하게 증명 | 공인 TSA 타임스탬프 + 해시로 위·변조 여부를 외부 도구(openssl)로 독립 검증 |
| G3 | 등록 이후 **내용이 바뀌지 않았음**을 보장 | 해시 체인(원장) 무결성 검사 통과/실패를 즉시 확인 |
| G4 | 아이디어의 발전 과정을 기록 | 수정은 덮어쓰기가 아닌 "개정판"으로 쌓이고 각 판마다 시점 증명 |
| G5 | 증명 자료를 손쉽게 제출 | 확인서(인쇄용) 및 증명 번들(zip) 다운로드 |
| G6 | **아이디어 대출**: 적립된 아이디어를 사업자가 빌려 사업화하고, 성과(이익 배당·지분)를 창안자에게 돌려줌 (v2~v4, §10) | 첫 대출 계약 1건 성사 → 성과 배분 1건 지급 |

### 비목표 (Non-goals)
- 특허 출원 대행, 법률 자문, 아이디어의 신규성·진보성 판단
- v1(MVP)에서의 거래 기능 — 아이디어 대출은 v2부터 단계적으로 도입 (§10)
- 지분·대금의 **직접 보관** — 신탁사·에스크로 등 제휴 기관을 통해서만 예탁
- 지분의 쪼개기·재판매 등 **유통 기능** (증권 규제 대상이 될 수 있음)
- 블록체인 토큰 발행

## 3. 사용자

| 페르소나 | 니즈 |
|----------|------|
| 개인 창작자·발명가 | 떠오른 아이디어를 바로 적고 날짜를 확보 |
| 스타트업·기획자 | 사업 아이디어, 기획안의 선행 시점 확보 |
| 기업 R&D·사내 제안제도 | 직원 제안의 접수 시점·제안자 기록 |
| 공동 연구자 | 누가 언제 어떤 기여를 했는지 기록 |
| **사업자** (v2~) 스타트업·중소기업·지자체 | 검증된 아이디어를 빌려 새 사업을 시작하고, 성과에 연동해 대가를 치름 |

## 4. 핵심 사용자 시나리오

1. **등록**: 사용자가 제목·본문·태그·작성자·첨부파일을 입력하고 "등록" → 시스템이 해시를 계산하고 원장에 추가, 공인 TSA로부터 타임스탬프 토큰을 받아 저장 → 등록번호와 확인서 표시.
2. **개정**: 기존 아이디어에서 "개정판 등록" → 새 판이 원본에 연결되어 별도 시점 증명을 받음. 원본은 변하지 않음.
3. **확인서 발급**: 상세 화면에서 "확인서" → 등록번호, 해시, 등록 시각, TSA 시각, 원장 위치가 담긴 인쇄용 페이지.
4. **증명 번들 다운로드**: 원문(정규화 JSON), 첨부파일, TSA 토큰(.tsr), 검증 방법 안내가 담긴 zip.
5. **검증**:
   - 원장 전체 무결성 검사 (변조된 항목 위치 표시)
   - 증명 번들 업로드 → 해시 재계산·토큰 일치·원장 등재 여부 확인
   - 파일 하나를 올려 "이 파일이 언제 등록됐는가" 조회 (해시 조회, 파일은 서버에 보내지 않음)

## 6. 비기능 요구사항

- **프라이버시**: 외부 TSA로는 해시값(32바이트)만 전송. 아이디어 본문은 로컬에만 저장.
- **독립 검증성**: 이 시스템이 없어져도 번들 + openssl 만으로 시점 검증 가능.
- **설치 용이성**: Python 3 표준 라이브러리만으로 실행 (외부 패키지 설치 불필요).
- **내구성**: 원장은 추가 전용(append-only). 백업은 데이터 폴더 복사로 충분.
- **사용성**: 한국어 UI, 모바일 폭에서도 사용 가능. 전문 용어 대신 쉬운 말 사용("해시"→"고유 지문", "타임스탬프"→"공인 시각"). 화면 흐름과 문구는 [사용자 안내서](USER_GUIDE.md)를 기준으로 한다.

## 7. 증거력에 대한 한계 고지 (UI·문서에 표기)

- 타임스탬프는 "**해당 시점에 이 내용이 존재했음**"을 증명할 뿐, 독창성이나 최초 창안자임을 증명하지는 않는다.
- 법적 증거력은 관할·사안에 따라 다르며, 중요한 사안은 변리사·변호사와 상담을 권장한다.
- 보완 수단: 원장 헤드 해시 정기 공개, 공증, 한국지식재산보호원 "영업비밀 원본증명" 서비스 병행.

## 8. 성공 지표

- 등록 성공률(TSA 포함) ≥ 99%
- 원장 무결성 검사 오탐 0건
- 번들 → openssl 외부 검증 성공률 100%

## 9. 릴리스 계획

| 단계 | 이름 | 범위 | 형태 |
|------|------|------|------|
| **v1** | 증명 (MVP) | F1–F11 | 단일 사용자 로컬 웹앱 |
| **v2** | 열람 통제 | F12–F17, F22, 로그인·조직 | **온라인 서비스로 전환** (창안자와 사업자가 만나야 하므로) |
| **v3** | 대출 계약 | F18–F20(수작업 정산) | 표준 계약 템플릿, 법률 파트너 검토 |
| **v4** | 예탁·정산 | F20(자동), F21 | 신탁사·에스크로 제휴 |
| **v5** | 마켓 | F23 | 검색·추천, 사례 공개 |

- v2 이전에 **수작업 실험**: 창안자 10명, 사업자 3곳을 직접 연결해 대출 계약 1건을 성사시켜 모델을 검증한다.
- OpenTimestamps(비트코인) 이중 앵커는 v2 이후 선택 과제.

## 10. 사업 비전 — 아이디어 대출

> 출처: 대표의 1호 아이디어 [IB-20261118-000001](../ideas/IB-20261118-000001/idea.md) (공인 시각 2026-11-18 05:14:34 UTC) · 상세 검토: [IDEA-001](IDEA-001_아이디어대출_사업모델.md)

**아이디어를 은행 예금처럼 적립하고, 기업이 빌려 가 사업화하면, 성과의 일부를 창안자에게 돌려준다.**

- **포지셔닝**: 증명 서비스(v1)는 아이디어를 적립하는 **입구**이고, 아이디어 대출(v2~v4)이 **본 수익 모델**이다.
- **핵심 차별점**: 다음 두 가지를 한 곳에서 공인 시각으로 남긴다. 거래 과정의 아이디어 탈취를 막는 증거가 된다.
  - 창안자가 언제 가지고 있었는가 (적립 시각)
  - 사업자가 언제 봤는가 (열람 기록)
- **창안자 보상 방식**: 계약금, 매출 로열티, 이익 배당, 지분 중에서 선택한다.
  - 기본 권장은 "소액 계약금 + 지분"이다. 매출 추적이 필요 없다.
  - 요율은 검증이 필요한 가설이다.
- **플랫폼 수익**: 거래 성사 수수료, 정산 수수료, 증명 구독료 (구조 미정)
- **용어 원칙**: "대출", "예탁"은 브랜드 비유로만 쓴다. 계약서와 약관에는 "사용권 허락", "성과 배분"으로 표기한다.
- **출시 전 법률 확인**: 신탁업·자본시장법 해당 여부, 부정경쟁방지법 아이디어 탈취 조항의 활용, 창안자 소득 과세, 직무 아이디어 귀속

### 미결정 사항
1. 첫 사업자 대상: 스타트업 / 중소기업 / 지자체·공공
2. 기본 보상 방식: 지분형 우선 / 로열티형 우선
3. 플랫폼 수수료 구조와 요율
